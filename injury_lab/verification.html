A defect found in this lab’s own code, and what it changed

Reported because a checker that only tests other people’s work is decoration.

  • The injury-report parser was reading its own provenance header as page content. The depth-chart parser stripped the header first; the report parser did not. Fixed by routing both through body_lines(). The published row set is identical before and after (139 rows, byte-compared), because no header line happens to match a row shape - so no number on this site moved. The class of bug is nevertheless real: the same mistake in the join layer had earlier made every club chart unfindable, which is why the 17 replacement rows exist only after the fix.
  • A unit-map lookup was written as a no-op. conventions.py assigned the captured name instead of the mapped unit. Nothing downstream used that field, and the fix left the mapping output unchanged; it is recorded because it would have mattered the moment a cross-club count read it.
  • One claim in this lab’s draft was wrong about a club page and was withdrawn in the capture file rather than deleted. See H20.

Known limit of this layer

P7 proves the published rows match the retained capture. It cannot prove the capture matches the live page, because the live page moves (H01). The second layer is python3 -m injury_lab.capture verify --live, which re-opens each URL and reports which published rows are no longer present verbatim. That command cannot run in this sandbox (there is no route from here to nfl.com), and it has therefore not been run here. Recording that as a limit is better than implying a check that did not happen. This is also why flag H20 matters: an error in the capture layer itself — and one was found and corrected in this directory — is invisible to P7 by construction.

Reproduce the whole thing

python3 -m injury_lab.capture index    # hash and index the retained captures
python3 -m injury_lab.parse             # captures -> injury rows and depth strings
python3 -m injury_lab.join              # rows x charts x pinned games.csv
python3 -m injury_lab.signals           # pre-registered family, gates, pilot
python3 -m injury_lab.builds            # repo index and id collisions
python3 -m injury_lab.build_site         # regenerate the pages
python3 -m injury_lab.check_site         # fail closed on any rule

The pipeline is stdlib-only, so it runs in CI with no dependencies; the heavier statistical gates live in scripts/gates.py and require numpy/pandas/scipy, which is why this lab delegates IG5 and IG9 rather than reimplementing them with softer maths.
