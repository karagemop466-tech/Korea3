Suggestion register

Every row links to an official source or repository file. Status 'Pending' means awaiting reviewer decision. Status 'Blocked' means an external dependency prevents implementation.

Each suggestion has a stable ID and a decision path. Nothing is implemented without explicit review.
ID Priority Suggestion Impact & rationale Status / blocker Decision path Official source
S01 High Add real-time NFL injury report ingestion The NFL publishes injury reports Wed–Fri each week. Automating ingestion of these reports would enable the injury-tracker page to show live data rather than a framework. Impact: directly feeds line adjustments and prop analysis. Pending — requires licensed data feed or official NFL API access. Manual review → approve data source → implement pipeline → verify output repo ↗ NFL-STATS ↗
S02 High Integrate live closing-line prices from a licensed operator No strategy can be verified without actual operator prices. DraftKings and FanDuel publish their own settlement rules but not historical price archives. A licensed data feed would close the largest evidence gap in this repository. Blocked — no licensed operator API was available. Obtain data-use agreement with DraftKings or FanDuel → pipe prices into pipeline/ → re-run strategies DK-SPREAD ↗ FD-CT-RULES ↗
S03 Medium Expand strategy library with weather-adjusted totals S6 (Weather under) showed +0.58% ROI but failed G5 (holdout). Adding wind-chill and precipitation intensity as separate features, plus dome/roof status, could sharpen the signal. Framework exists in pipeline/features.py; empirical test blocked by licensed price gap. Define weather features → backtest against closing lines → gate-check → publish or reject repo ↗ repo ↗
S04 Medium Build a rest-advantage model with travel distance S4 (Rest asymmetry) passed 4/9 gates. Adding cross-country travel, short weeks, and Thursday-to-Sunday turnarounds as interaction terms may improve the edge estimate. Data for rest days exists in the nflverse games.csv; travel distance requires an external source. Compute travel distance per game → add as feature → re-run S4 → gate-check repo ↗ NFL-SCHEDULE ↗
S05 Medium Add referee crew data as a line adjustment factor S7 (Referee crew total tendency) passed 4/9 gates with -4.29% ROI. The direction is negative but the crew-level variance is real. Referee assignments are published weekly by NFL Football Operations. Official referee assignment data is publicly available on operations.nfl.com. Scrape weekly referee assignments → compute crew tendencies → test as overlay on S3/S6 NFL-GAMEDAY ↗ repo ↗
S06 Low Create a situational spot-rating system Look-ahead spots, let-down spots, revenge games, and short-week prime-time games are folklore. A rigorous test against the nflverse data could confirm or deny each category. Requires tagging each game with a situation code; outcome data is available. Define spot categories → tag games → test each as a standalone strategy → gate-check repo ↗ NFL-SCHEDULE ↗
S07 Low Add a public suggestion submission form Allow site visitors to submit strategy ideas or data sources. Each submission would be triaged on this page with a status and decision trail. No infrastructure exists yet; GitHub Issues could serve as the intake channel. Decide on intake channel (GitHub Issues, Google Form, or custom) → define triage SLA → publish intake link repo ↗ repo ↗
S08 Low Publish model-implied lines for upcoming games with uncertainty bands The model already generates spread and total estimates for unplayed games (data/derived/own_lines_upcoming.csv). Adding bootstrap confidence bands around each estimate would make the output more honest. Model exists; confidence bands require 2,000 bootstrap resamples per game which is computationally feasible. Implement bootstrap band → publish on own-lines page → verify coverage on holdout repo ↗ NIST-BOOT ↗
