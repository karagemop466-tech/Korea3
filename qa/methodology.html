Method

How this verification was done, and what it cannot do

Reproducible checks only. No value was copied from a screenshot, a model's memory or an earlier session's summary without recomputation. Where recomputation was impossible, the row says "unverified" and stays visible.

The five kinds of check

KindWhat it meansExample
Upstream re-derivationRe-download the pinned commit from the GitHub API and compare SHA-256 with both the recorded hash and the local file.5/5 nflverse files matched at a270278f.
RecomputationRecompute a published number from committed data with an independent implementation.16,439 settlements; 11/11 strategy ROIs; MAE 10.670.
Arithmetic identityA value that must hold by definition.110/210 = 52.38%; φ break-even 0.09751.
Structural crawlParse every page and resolve every href/src against the published tree, case-sensitively, including anchors.108 pages, 2,991 internal links, 0 broken.
Platform APIAsk GitHub for deployment and CI state rather than assuming it. Pages status and latest Actions conclusion.

What is deliberately not claimed

  • External sources were not re-read. This sandbox reaches github.com and api.github.com only. nfl.com, nist.gov, operator help centres and pro-football-reference.com were unreachable, so those 4,270 links are counted and listed, never marked checked (F-10).
  • No performance figure is a settlement record. Returns are backtests on a third-party open dataset, not verified wagers or prices from a sportsbook.
  • No correlation is presented as a strategy. A dependence estimate is not an edge; a parlay needs φ ≈ 0.0975 at −110 before dependence alone helps, and nothing here reaches it.
  • Two published point estimates remain unverified because their filters cannot be reproduced from the repo: the spread × total φ values (F-06) and the 6,340-game sample (F-07).
  • This is not legal advice. The data-rights position is inherited and unverified here; the repository redistributes no NFL.com content.

Reproduce

python3 qa/check_links.py     # repository-wide link + asset crawl
python3 qa/verify.py          # every numeric claim, recomputed; writes verification.json
python3 qa/build_site.py      # render these pages from that JSON

Dependencies: Python 3.11 with pandas and numpy, plus the gh CLI for the platform checks. Without network access the upstream and deployment rows report BLOCKED instead of guessing.

Checker limitations found while building this page

The first crawl reported 93 failures. 35 were this checker's own blind spots: pages that set <base href="/Korea3/"> (13 pages) and links written as /Korea3/… were being resolved against the filesystem instead of the site root. Both are handled now. That reduction is recorded here rather than quietly fixed, because a verifier that over-reports is as misleading as one that under-reports.
