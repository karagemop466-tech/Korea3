# Independent QA of a parallel standings-verification snapshot

**Snapshot:** session `arena/d118ca7e-korea3`, commit [`99832574a9e603081c08d175a2bd4f35b114ddb7`](https://github.com/karagemop466-tech/Korea3/commit/99832574a9e603081c08d175a2bd4f35b114ddb7), reviewed on 2026-11-01 UTC. The session may have fixed these issues later; this report does not evaluate later commits. No files owned by that session were modified.

**Scope:** independently reviewed the standings comparison code and summary, not the later modelling, betting strategies, or all individual source rows. Opened the [2025 NFL standings](https://www.nfl.com/standings/division/2025/REG), the [2026 NFL standings](https://www.nfl.com/standings/division/2026/REG), and the [DraftKings spread explanation](https://support.draftkings.com/dk/en-us/what-is-a-point-spread-bet?id=kb_article_view&sysparm_article=KB0010595). The [nflverse dataset author's documentation](https://github.com/nflverse/nfldata/blob/master/DATASETS.md#games) was consulted only for that dataset's own field convention; nflverse is not an official NFL or operator source.

| Finding | Evidence and requested correction | Official source for context |
|---|---|---|
| Team-code mapping is omitted from the missing/extra summary | The per-team comparison maps `AZ` to `ARI`, but the raw set difference does not. In both snapshot reports, the same team is simultaneously matched and reported missing/extra. Normalize both sets before reporting and explicitly detect alias collisions. | [NFL 2025 standings](https://www.nfl.com/standings/division/2025/REG); [NFL 2026 standings](https://www.nfl.com/standings/division/2026/REG) |
| Missing zero-valued team can be falsely marked MATCH | `derived.get()` substitutes all-zero values when a mapped team is absent. A synthetic zero-record test produces `MATCH` even though the team is missing. Mark missing teams `UNVERIFIED` or `MISSING`, fail the integrity gate, and check uniqueness/completeness. This is a demonstrated code-path issue, not a claim that an actual team's results are zero. | [NFL standings and definitions](https://www.nfl.com/standings/division/2025/REG) |
| Aggregate validation does not validate individual game scores | Matching team wins/losses/ties and total points is useful, but multiple different sets of individual game scores can have identical aggregates. `games_covered_by_verified_standings` must not be interpreted as every game being officially verified. Require a specific official game record and a per-field comparison for each published game. | [NFL standings](https://www.nfl.com/standings/division/2025/REG); [example official NFL gamebook](https://static.www.nfl.com/image/upload/v1766722063/gamecenter/f91b71fe-311e-11f0-b670-ae1250fadad1.pdf) |
| Spread-sign wording conflicts with field convention | The snapshot board says a negative home spread means the home team is favoured, which is a sportsbook-style quoted spread. Its own comparison code and the upstream dataset's documentation use the opposite sign for `spread_line`: positive means the home team is favoured. Distinguish the dataset field from a sportsbook quote; do not conflate either with verified executable odds. | [DraftKings point spread](https://support.draftkings.com/dk/en-us/what-is-a-point-spread-bet?id=kb_article_view&sysparm_article=KB0010595); [dataset publisher's field definition](https://github.com/nflverse/nfldata/blob/master/DATASETS.md#games) |
| Dynamic-source capture and usage | The 2026 standings are a moving target. Preserve retrieval time in UTC, the exact source or permitted snapshot, and content version/hash. An NFL gamebook carries a stated use restriction; check permission before automated extraction or redistribution. | [NFL 2026 standings](https://www.nfl.com/standings/division/2026/REG); [NFL gamebook](https://static.www.nfl.com/image/upload/v1766722063/gamecenter/f91b71fe-311e-11f0-b670-ae1250fadad1.pdf) |
| Odds and performance are separate | Standings checks cannot verify bookmaker odds, execution, settlement, or backtest ROI. Without operator-origin, dated quotes and settlement evidence, those fields remain blank and flagged rather than presented as verified. | [DraftKings settlement terms](https://support.draftkings.com/dk/en-us/glossary-of-betting-terms?id=kb_article_view&sysparm_article=KB0010398) |

## Reproduction

`python3 audit/reproduce_standings_qa.py` loads the snapshot's actual `pipeline/verify.py` from Git into memory, substitutes a stub writer, and runs two **synthetic** fixtures. It reproduced both the team-code summary inconsistency and the missing-zero-team false match. It does not alter the other session's branch or generate real-world figures. The snapshot commit must be present in the local Git object database; it was fetched from that session's remote branch during this audit.

Separately, an in-memory inspection of the snapshot's two recorded standings sets confirmed that applying its own `AZ` → `ARI` mapping removes the reported missing/extra-code differences. This check does not establish that the standings transcriptions or every game in the underlying community dataset are correct. All numeric strategy, line, performance, correlation and reward claims remain outside this QA's scope.
