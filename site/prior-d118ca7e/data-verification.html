How each row is re-checked on every run

Storing the official values would break the data-rights rule the rest of this project follows (F-10), so the repository stores a sha256 digest of each official row instead (data/official/row_hashes.json). Every pipeline run recomputes our own aggregates, hashes them with the same canonical string {season}|{team}|{w}|{l}|{t}|{pf}|{pa} and compares them. A reviewer reproduces the check with one line by hashing their own reading of the official page — the equality holds or it does not, and no official value is republished.

python3 -c "import hashlib;print(hashlib.sha256(b'2025|ARI|3|14|0|355|488').hexdigest())"
→ 7651a69ab2bed8b3406643d36630d8a90e867f7c27f01e612b1a0a28c5172f17

That worked example is the only row whose values appear anywhere in this repository: it exists so the recipe can be tested against data/official/row_hashes.json, and it is not used as data.
